# StudyAI — Personal Build Phases (Solo Developer Guide)

This document breaks down the entire StudyAI build into 9 strict, chronological phases. It is designed for a single developer building this for personal use (1-2 exams). 

There is no scaling, no authentication, no Temporal, and no complex deployment infrastructure here. Just the raw, step-by-step instructions to get the 12-agent pipeline and frontend working locally for your own exams.

---

## Phase 1: Environment & Database Setup

**Goal:** Lay the foundation so agents have somewhere to read from and write to.

1. **Folder Structure Initialization:** Create the full nested directory tree exactly as shown above.
2. **Environment Variables:** Create `backend/.env`. Add your API keys for Google (Gemini 2.0 Flash — free via AI Studio), Groq, and Cerebras. No Anthropic key required — Claude has been replaced by Gemini 2.0 Flash.
3. **Database Schema:** 
   - Create `backend/database/migrations/001_initial_schema.sql` by copying the SQL from the Technical Reference.
   - Run this SQL on a free Supabase project to create all tables and enable Realtime on `units` and `topics`.
4. **Manual Source Directory:** 
   - Create `backend/source_map/upc_registry.json` and add an entry for your test exam.
   - Create `backend/source_pdfs/{upc}/` and place your target `syllabus.pdf` and `pyq_xxxx.pdf` documents there.

---

## Phase 2: Source Data Ingestion (Agents 1 & 2)

**Goal:** Extract and normalize syllabus and PYQ data from your manual PDFs.

1. **Decoder (Agent 1):** Write `backend/pipeline/agents/01_decoder.py`. It reads `upc_registry.json` and writes the initial record into the Supabase `papers` table.
2. **Researcher (Agent 2):** 
   - Create `backend/pipeline/prompts/researcher.txt` and `backend/pipeline/schemas/syllabus_extraction_schema.json`.
   - Write `backend/pipeline/agents/02_researcher.py` using Gemini 2.5 Pro to read `source_pdfs/{upc}/syllabus.pdf` and output the strict JSON.
3. **Researcher Verifier (Agent 2B):** Write `backend/pipeline/agents/02b_researcher_verifier.py`. Pass raw PDF text and Agent 2's JSON to Groq (Llama 3) for a binary pass/fail verification.
4. **PYQ Normaliser (Agent 2C):** 
   - Create `backend/pipeline/schemas/pyq_normalised_schema.json`.
   - Write `backend/pipeline/agents/02c_pyq_normaliser.py` using Groq to standardize all raw PYQ text into the expected JSON format.

---

## Phase 3: Paper DNA & Mapping (Agents 3 & 4)

**Goal:** Give the system an exam-oriented "brain" before writing notes.

1. **Paper DNA (Agent 3):** 
   - Create `backend/pipeline/prompts/paper_dna_topic.txt`, `paper_dna_language.txt`, and `backend/pipeline/schemas/paper_dna_schema.json`.
   - Build scripts inside `backend/pipeline/agents/03_paper_dna/` to run **Gemini 2.0 Flash** on the normalized PYQs. Write output to the `papers.paper_dna` column.
2. **Mental Model Mapper (Agent 4):** 
   - Create `backend/utils/cycle_detector.py` to prevent infinite prerequisite loops.
   - Create `backend/pipeline/prompts/mapper.txt`.
   - Write `backend/pipeline/agents/04_mental_model_mapper.py` (**Gemini 2.0 Flash**) to map syllabus sequence and concept bridges based on Paper DNA.

---

## Phase 4: Core Content Generation (Agent 5)

**Goal:** Build the single most important agent in the system.

1. **Prompt Components:** 
   - Create `backend/pipeline/prompts/writer_invariant.txt` (the strict rules).
   - Create `backend/pipeline/prompts/writer_variant.py` (a script to inject current topic DNA & concept bridges).
   - Create `backend/pipeline/schemas/topic_schema.json`.
2. **Writer (Agent 5):** Write `backend/pipeline/agents/05_writer.py` (**Gemini 2.0 Flash** — free). It runs **per topic**, takes the assembled prompt, and MUST output JSON matching `topic_schema.json`.
3. **Iterative Tuning:** Test `05_writer.py` locally on 2 topics. Tweak `writer_invariant.txt` repeatedly until the depth and format are perfect.

---

## Phase 5: Verification & Trust (Agents 6, 7 & 8)

**Goal:** Ensure the Writer didn't hallucinate or miss anything.

1. **Coverage Checker (Agent 6):** Write `backend/pipeline/agents/06_coverage_checker.py` (Groq Llama 3) to cross-reference output JSON with the original Syllabus JSON.
2. **Verifier (Agent 7):** Create `backend/pipeline/prompts/proof_verifier.txt` and write `backend/pipeline/agents/07_verifier.py` (Cerebras) to logically check math/proofs.
3. **Critic (Agent 8):** 
   - Create `backend/pipeline/prompts/critic_constitution.txt` (your ultimate list of "what makes a note good/bad for DU exams").
   - Create `backend/pipeline/schemas/diff_schema.json`.
   - Write `backend/pipeline/agents/08_critic.py` (**Gemini 2.0 Flash**). It must output surgical JSON diffs only (field, issue, correction, severity).

---

## Phase 6: Correction & Patching (Agents 9, 10, 11, 12)

**Goal:** Automatically apply the Critic's feedback and finalize the unit.

1. **Rewriter & Micro-validator (Agents 9 & 9B):** Write `backend/pipeline/agents/09_rewriter.py` to apply the Critic's JSON patches, and `09b_micro_validator.py` to verify the rewrite succeeded.
2. **Final Examiner (Agent 10):** Create `backend/pipeline/prompts/final_examiner.txt` and write `10_final_examiner.py` to ensure every PYQ is addressed in the notes.
3. **Patcher (Agent 11 & 11B):** 
   - Create `backend/pipeline/prompts/patcher.txt` and `backend/pipeline/schemas/unit_schema.json`.
   - Write `11_patcher.py` and `11b_post_patch_regen.py` to add missing PYQs and generate the `conceptual_summary` at the unit level.
4. **Consistency Checker (Agent 12):** Write `12_consistency_checker.py` to enforce uniform mathematical notation before saving the final topic JSON to Supabase.

---

## Phase 7: Backend Orchestration

**Goal:** Tie all 12 scripts together so they run in sequence.

1. **Database Clients:** Write `backend/database/client.py` and `backend/database/queries.py` to handle reading/writing topic/unit statuses to Supabase.
2. **Orchestrator:** Write `backend/pipeline/orchestrator.py`. This script receives a UPC, calls Decoder through Mapper, then fires Agent 5-12 for each topic, updating the database status (`queued` -> `generating` -> `complete`) at each step.
3. **API Entry:** Write `backend/main.py` using FastAPI with a single endpoint to kick off the orchestrator as a background task. Test it locally.

---

## Phase 8: Frontend Construction

**Goal:** Render the JSON database into beautiful notes.

1. **Next.js Initialization (Stage 8.1):** Set up a clean Next.js app in the `frontend/` directory with Tailwind CSS and Framer Motion. Create types and configuration files. [COMPLETED]
2. **Supabase Connections:** Write `frontend/lib/supabase.ts` and `frontend/lib/queries.ts` to connect to your remote database and listen to Realtime changes on the `units` table. [COMPLETED]
3. **Component Mapping:** Create individual React components in `frontend/components/notes/` for every field in `topic_schema.json` and UI components. [COMPLETED]
4. **Progressive Rendering:** Write `frontend/app/paper/[upc]/page.tsx` to automatically render new units on the screen the moment their status flips to `complete` in Supabase. [COMPLETED]

---

## Phase 9: End-to-End Personal Testing

**Goal:** Dogfood the product for your own exams.

1. Load **one theory paper** and **one numerical paper** into `backend/source_pdfs/`.
2. Trigger `backend/main.py` via an API call locally.
3. Open your Next.js app and watch the pipeline orchestrate.
4. Study directly from the output.
5. If the notes fail to meet your standards, edit `writer_invariant.txt` or `critic_constitution.txt`, wipe the Supabase rows, and run it again until perfect.
