THE ELEVATED PHILOSOPHY — WHAT IS NEW IN THIS PLAN
================================================================

Six additions that push this from well-designed to award-worthy.
Each one is justified below. None are decorative.

1. FILM GRAIN TEXTURE LAYER
   A subtle SVG noise overlay at ~3.5% opacity across the entire app.
   This is what separates Basement Studio from everything else.
   It makes the screen feel like it has material, not like a flat monitor.
   You do not consciously notice it. You feel it.
   Invisible to the eye. Felt by the body.
   Reference: basement.studio — grain is what makes their dark feel warm.

2. CUSTOM CURSOR SYSTEM
   Replace the browser default with a warm-white dot (6px) and a trailing
   ring (24px) that follows with spring lag.
   On hoverable elements it morphs — expands into amber ring, or on
   pipeline cards shows a subtle rotation.
   On the reading page, hovering a block label shows "FLAG" inside the ring.
   On mobile: disabled entirely.
   Why it matters: the cursor is the user's hand. Making it feel physical
   makes the entire site feel physical. This is the single most Awwwards-
   coded element you can add.

3. CHARACTER-LEVEL TEXT REVEAL
   Instead of blocks fading in, the hero headline, unit titles, and topic
   names reveal word by word from a mask clip.
   Technique: overflow hidden container, each word wrapped in a span,
   translateY 100% → 0 with staggered spring.
   The text feels like it is being carved out of darkness rather than
   appearing on top of it.
   Reference: Linear's homepage headline. Vercel's hero. Every Awwwards
   Site of the Year for the past 4 years.

4. THE MANIFESTO PAGE (new page — does not exist in old plan)
   A single full-scroll page visible to first-time visitors before homepage.
   Huge editorial typography. Scroll-scrubbed text that highlights word
   by word as you scroll down. A single number counter: 12 AGENTS, animated
   0 → 12 as you scroll. A final CTA at the very bottom: "Enter your paper."
   This is your story. It converts. It gives StudyAI a reason to exist
   beyond the feature list.
   Stored at route /about or shown as a pre-homepage splash (one-time).

5. FOCUS MODE ON READING PAGE
   A toggle in the topbar enters Focus Mode.
   In focus mode:
     - Sidebar collapses to 20px (just the priority dot column)
     - Topbar minimizes to a 2px amber progress line
     - Everything non-essential fades to 20% opacity
     - Reading column expands to fill the space
   Spring animation on all transitions. 300ms.
   A student in an exam revision session should be able to disappear
   into the content. This feature enables that.

6. AMBER INK REVEAL FOR DEFINITIONS
   When a Definition block enters the viewport, the amber left border
   draws itself from top to bottom (SVG pathLength 0 → 1, 400ms easeOut).
   Then the definition text reveals word by word.
   Sequence: border draws → text appears. 600ms total.
   This is the single most memorable micro-interaction on the reading page.
   It makes the definition feel like it is being written in real time.

7. SCROLL-EDGE READING PROGRESS
   A 2px amber line on the very LEFT EDGE of the screen (not a topbar bar —
   the literal left edge of the viewport) fills as the student scrolls
   through a unit. Feels like a bookmark being drawn in the margin.
   At 100%, a soft pulse radiates from the bottom of the line.
   This replaces or complements the topbar progress — it lives in the
   margin, not competing with content.

8. DEAD TIME ANIMATION ON PIPELINE GRID
   When agents are QUEUED and nothing is happening, every 6–8 seconds
   a faint shimmer/pulse passes through the queued cards from left to right
   like a sonar ping scanning the grid. Opacity wave: 0.45 → 0.65 → 0.45,
   spring, 1200ms sweep.
   It communicates: the system is alive and waiting, not frozen.
   The difference between a loading state that builds trust and one that
   creates anxiety.

9. SONIFICATION (OPTIONAL, OFF BY DEFAULT)
   When the pipeline marks an agent COMPLETE (checkmark draws):
   a barely-audible soft click plays. 30ms, 40dB.
   When all 12 complete: a single clean warm tone.
   Toggleable in settings. Off by default.
   Reference: Linear's done sounds — makes digital work feel real.

10. NOISE TEXTURE ON PIPELINE CARDS
    Each agent card gets a very faint SVG noise texture on its background
    (same technique as global grain, applied at different scale per card).
    Combined with 3D tilt, the cards feel like physical objects with
    material — not flat rectangles.

COLOUR PALETTE:
---------------
All colours as CSS custom properties in globals.css.
Nothing hardcoded anywhere in components. Ever.

Backgrounds (dark to light — 5 levels of depth):
  --bg-base:        #0a0908   (the void — warm near-black, NOT pure #000)
  --bg-raised:      #111009   (sidebar, topbar backgrounds)
  --bg-surface:     #1a1813   (section dividers, inactive areas)
  --bg-card:        #1e1c16   (card default state)
  --bg-card-hover:  #252319   (card hover state)

Why warm not cool: The amber accent needs a warm base to feel cohesive.
Pure black (#000000) with amber looks like a warning sign. Warm dark
with amber looks like a lamp in a dark library. That is the feeling.

  --border-subtle:  rgba(255,255,255,0.06)   (default, always present)
  --border-default: rgba(255,255,255,0.10)   (cards, inputs)
  --border-strong:  rgba(255,255,255,0.18)   (hover states, active)

  --text-secondary: #9a9485   (supporting text, descriptions)
  --text-tertiary:  #5a5548   (labels, metadata, placeholders)

Why warm not pure white: #ffffff on #0a0908 is too clinical. #f0ece0
is warm enough to feel like paper, cold enough to be readable at density.

TYPOGRAPHY SYSTEM:
------------------
Three fonts. Three roles. Never mixed or swapped.

INSTRUMENT SERIF — all academic content
  Source: fonts.google.com/specimen/Instrument+Serif
  Used for: unit titles, definitions, PYQ question text, hero headline,
            conceptual summaries, analogies, paper names, large display text,
            manifesto page body, the "carved from darkness" hero text
  Why: it carries weight and authority. A definition in Instrument Serif
       reads like something from a textbook. The same text in Inter
       reads like a tooltip. Font choice IS meaning.
  Weights: 400 regular, 400 italic
  Sizes: 72px hero, 120px manifesto display, 48px paper title,
         40px unit title, 18px definitions, 15px PYQ text, 13px summaries
  CRITICAL: load both normal and italic styles explicitly in next/font.
            Without italic specified, faux-italic is applied — visually wrong.

SYNE — all UI and navigation
  Source: fonts.google.com/specimen/Syne
  Used for: nav labels, badges, buttons, section headers, metadata rows,
            card titles, body text in UI
  Why: geometric, strong, slightly unusual. Not Inter. Not Geist.
       It has personality without being decorative.
  Weights: 400, 500, 600, 700, 800
  Sizes: 10px labels (uppercase), 11px metadata, 12px secondary UI,
         13px primary UI, 14px body, 17px card titles, 18px unit names

DM MONO — all data and mathematics
  Source: fonts.google.com/specimen/DM+Mono
  Used for: all formulas (KaTeX), step numbers, UPCs, agent identifiers,
            year references, status text, pipeline ticker, stat values,
            time estimates, cursor label text (when cursor shows "FLAG" etc.)
  Why: precise, technical, readable at small sizes. Every number and every
       formula gets mono treatment — this creates a visual language where
       "data" is always identifiable.
  Weights: 400, 500
  Sizes: 10px labels, 11px metadata, 12px formulas, 13px steps, 15px answers

LOADING FONTS IN NEXT.JS:
  Import all three via next/font/google in app/layout.tsx.
  Assign CSS variables: --font-serif, --font-sans, --font-mono.
  Apply variables to <html> element.
  Never use @import in CSS — always next/font for performance.
  Always set display: 'swap' to prevent layout shift on load.

THE FILM GRAIN SYSTEM
================================================================

THE COMPONENT: <GrainOverlay />
  position: fixed
  inset: 0
  z-index: 9999
  pointer-events: none
  mix-blend-mode: overlay
  opacity: var(--grain-opacity) — 0.035

IMPLEMENTATION:
  Method 1 (preferred, Chromium): SVG feTurbulence filter on a rect
    <svg width="100%" height="100%">
      <filter id="grain">
        <feTurbulence
          type="fractalNoise"
          baseFrequency="0.65"
          numOctaves="3"
          stitchTiles="stitch"
        />
        <feColorMatrix type="saturate" values="0"/>
      </filter>
      <rect width="100%" height="100%" filter="url(#grain)"/>
    </svg>

  Method 2 (Safari fallback): pre-generated PNG noise texture at 200x200px,
    tiled via CSS background-repeat: repeat
    This is necessary because SVG filters are slow on Safari/iOS.

  ANIMATION — what makes it feel like film grain not a static texture:
    Every 80ms, update the feTurbulence seed attribute with a random value
    (0–1000 range). This creates the flickering grain feel.
    Use requestAnimationFrame at 12fps (throttled, not 60fps — grain does
    not need to be buttery smooth, slight choppiness IS the grain aesthetic).

  User agent detection:
    const isSafari = /^((?!chrome|android).)*safari/i.test(navigator.userAgent)
    if (isSafari) → use PNG fallback
    else → use SVG filter + animation

WHY THIS MATTERS:
  Without grain, dark UI feels like a flat monitor.
  With grain at 3.5%, it feels like there is material behind the content.
  Basement Studio, Obys Agency, Active Theory — every Awwwards-level dark
  site uses this. It is the single cheapest-to-implement highest-impact
  visual upgrade possible.

THE CUSTOM CURSOR SYSTEM
================================================================

THE COMPONENT: <CustomCursor />
  Disabled entirely on: touch devices, mobile screens < 768px

TWO ELEMENTS:
  cursorDot:
    width: 6px, height: 6px
    border-radius: 50%
    background: var(--cursor-dot) — #f0ece0 (warm white)
    position: fixed, z-index: 10000
    pointer-events: none
    Position: direct 1:1 with mouse via useMotionValue
    No spring lag — it IS the cursor, must feel instant

  cursorRing:
    width: 24px, height: 24px
    border-radius: 50%
    border: 1px solid rgba(240,236,224,0.25)
    background: transparent
    position: fixed, z-index: 9999
    pointer-events: none
    Position: useSpring(mouseX, { damping: 20, stiffness: 300 })
    The spring lag makes it trail the dot — communicates physicality

CURSOR STATES (morph based on what is being hovered):

  DEFAULT:
    dot: 6px warm white
    ring: 24px at 25% opacity, plain

  HOVERING A CARD / BUTTON:
    ring expands: 24px → 36px spring
    ring border-color: transitions to var(--cursor-ring) — amber
    dot: fades to 0 opacity (ring takes over as the indicator)

  HOVERING A DEFINITION BLOCK LABEL (the FLAG trigger zone):
    ring: expands to 40px
    Inside the ring: "FLAG" text appears in DM Mono 8px var(--text-tertiary)
    Uses a fixed label div that fades in inside the ring
    Cursor communicates its action before the user clicks

  HOVERING A PYQ QUESTION:
    ring: expands, color → var(--green) at 40% opacity
    Communicates: "this is exam content"

  HOVERING THE PIPELINE RUNNING AGENT CARD:
    ring: rotates continuously at 1 rotation per 3 seconds
    Reflects the card's own spinning loader — cursor mirrors the state

  HOVERING INTERACTIVE INPUT / QUICK CHECK:
    dot: scales to 3px
    ring: 16px — tightens (you are now in precision input mode)

  ON CLICK:
    dot: briefly scales to 10px then springs back
    ring: briefly scales down to 12px then springs back
    Spring: { damping: 12, stiffness: 400 } — snappy

  ON DRAG / MOUSEDOWN HELD:
    ring: scales to 20px, opacity increases to 50%

THE CHARACTER TEXT REVEAL SYSTEM
================================================================

Used on: Hero headline, Manifesto text, Unit titles, Topic names on
         reading page, Paper title on overview page.
NOT used on: UI labels, metadata, body prose, card descriptions.

COMPONENT: <MaskReveal text="..." tag="h1" delay={0} />

  MECHANISM:
    Split the text string by spaces into words.
    Each word wrapped in: <span style={{ overflow: 'hidden', display: 'inline-block' }}>
    Inside each span: <motion.span> with:
      initial: { y: '100%' }
      animate: { y: '0%' }
      transition: spring, damping: 20, stiffness: 100
      delay: index * 0.06 (60ms stagger between words)

  The overflow hidden parent clips the word during animation.
  The word appears to rise from below as if carved from darkness.
  No opacity change — purely position. This is cleaner than fade.

  VARIANTS:
    'standard' — 60ms stagger, spring as above. For headlines.
    'fast' — 30ms stagger, { damping: 25, stiffness: 200 }. For subheadings.
    'dramatic' — 80ms stagger, { damping: 15, stiffness: 80 }. For manifesto.

  SCROLL-TRIGGERED VERSION (manifesto + reading page):
    whileInView + viewport margin: '-100px'
    once: true (does not replay on scroll back)

  ACCESSIBILITY:
    prefers-reduced-motion: replace with simple opacity 0 → 1, 0.3s
    aria-label on the container with the full text string

LIB/PARSEFIELD.TS — THE JSON BUG FIX:

  parseField(raw):
    Try JSON.parse(raw)
    If parsed.meaning → return parsed.meaning
    If parsed.text → return parsed.text
    If parsed.content → return parsed.content
    If parsed.definition → return parsed.definition
    If string → return as-is
    Catch → return raw unchanged

  parseQuickCheck(raw):
    Try JSON.parse(raw)
    Return { question: parsed.question } ONLY
    NEVER return or expose parsed.answer to any component
    The answer field is backend-only. It never touches frontend.

  parseCommonMistakes(raw):
    Try JSON.parse(raw) — expects array
    Each item: { mistake: string, marks_lost: string }
    Return typed array
    Catch → wrap raw string in array with no marks_lost

  parseExaminerNote(raw):
    Try JSON.parse(raw)
    Return {
      text: string,
      years: string[],
      instruction_words: { word: string, count: number }[]
    }
    Catch → return { text: raw, years: [], instruction_words: [] }

  parseExample(raw):
    Try JSON.parse(raw)
    Return {
      problem: string,
      steps: { number: string, text: string }[],
      answer: string,
      common_error: string | null,
      example_type: string,
      verified: boolean,
      verification_mode: string
    }
    Catch → return null

KNOWN GOTCHAS — READ BEFORE BUILDING
================================================================

1. LENIS + FRAMER MOTION CONFLICT:
   They both want to control the RAF loop.
   Solution: @studio-freight/react-lenis, sync with Framer Motion useAnimationFrame.
   Do not install both independently without syncing.

2. NEXT.JS 15 + FRAMER MOTION:
   AnimatePresence with App Router requires "use client" on layout.
   Wrap in: components/PageTransition.tsx (client component).
   Do not put AnimatePresence directly in app/layout.tsx.

3. KATEX FLICKER:
   KaTeX renders async — raw LaTeX visible for a frame without handling.
   Solution: use react-katex (server-side rendering).
   <InlineMath math="x^2" /> and <BlockMath math="\sum_{i=1}^{n} x_i" />

4. MOUSE TRACKING PERFORMANCE:
   Never useState for cursor position — causes too many re-renders.
   Always useMotionValue. Apply directly to style props.

5. BACKDROP FILTER ON TOPBAR:
   backdrop-filter requires semi-transparent background to show.
   Solution: rgba(10,9,8,0.92) — not 'transparent'.

6. INSTRUMENT SERIF + NEXT/FONT:
   Requires both weight 400 AND style italic specified separately.
   Without italic: faux-italic (ugly synthetic slant).
   next/font syntax:
     Instrument_Serif({ weight: ['400'], style: ['normal', 'italic'] })

7. USESPRING INITIAL VALUE:
   Set initial value explicitly. Otherwise spring starts from 0 and
   you get a flash on first hover.

8. WILL-CHANGE OVERUSE:
   Degrades performance if used everywhere. Apply ONLY to:
   ZAxisText, agent card glow overlay, topbar, cursor elements.
   Nothing else.

9. QUICK CHECK ANSWERS:
   parseQuickCheck returns { question } only.
   Answer stripped at parse layer. Never pass to any component.
   Never log it. Self-assessment is subjective by design.

10. SYNE FONT WEIGHTS:
    Available: 400, 500, 600, 700, 800.
    Use 400 body, 700 card titles/labels, 800 manifesto/hero only.

11. GRAIN OVERLAY ON SAFARI:
    SVG feTurbulence animated at 12fps causes performance issues on Safari.
    Detect Safari via user agent → use static PNG noise texture instead.
    The PNG should be 200x200px, tiled via background-repeat: repeat.
    Source or generate: toptal.com/designers/subtlepatterns — noise textures.

12. MASK REVEAL + SCREEN READERS:
    The word-split technique creates many DOM elements.
    Always add aria-label with full text string to the container element.
    Without this, screen readers announce each word separately.

13. INK DRAW BORDER + CARD HEIGHT:
    The SVG path height must match the card height dynamically.
    Use a ResizeObserver on the card to update the SVG path endpoint.
    Or use: M 0 0 L 0 100% inside a viewBox="0 0 3 100" preserveAspectRatio="none"
    This stretches the SVG to match card height automatically.

14. FOCUS MODE + KATEX:
    When sidebar collapses and reading column expands, KaTeX formulas
    may reflow and require re-render. Wrap KaTeX in a key prop that
    changes when focus mode changes to force re-render.

15. CUSTOM CURSOR + FOCUS RINGS:
    Setting cursor: none globally hides the focus indicator on keyboard nav.
    Solution: on :focus-visible, show the 2px amber outline regardless.
    The CustomCursor only replaces the pointer cursor — it should never
    override focus visibility.
